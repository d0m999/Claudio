# 声音包库使用会话内 stale-while-refresh

面板和管理窗口可以立即显示本次 app 运行期间最近一次成功读取的声音包库快照，同时在后台刷新；首次尚无快照时显示明确加载态。快照不持久化到磁盘，任何相关写操作都使它失效，刷新结果携带单调递增的 revision，过期结果不得覆盖较新的写入或刷新结果。失败扫描不能确认或清除尚未读取成功的 invalidation。快照只承载声音包自身的磁盘事实；当前选择、星标、静音与面板显示集始终由最新用户配置同步派生，不因这些配置变化重新扫描声音包。

第一阶段不持续监听文件系统。app 内写操作显式失效相关快照；打开面板、重新展示管理窗口或 app 重新获得焦点时，在后台检查目录 metadata，只重新读取发生变化的声音包。观察请求若在一次扫描途中到达，必须合并为恰好一次 follow-up：该扫描可能已经越过被外部改动的包，不能把较晚观察静默算进较早结果。由一个写入方触发的跨界面通知只能有一个扫描 owner，另一界面只订阅同一状态流，避免把同一次写误当成较晚观察。窗口持续处于前台期间发生的 Finder 外部修改不承诺逐秒更新，但必须在下一次展示或激活时收敛。该模型用短暂、受控的陈旧换取窗口即时响应，同时避免建立第二套磁盘真相源、把 UI 状态固化进扫描缓存，或为尚不存在的实时外部编辑需求承担 FSEvents 的事件风暴与半成品状态复杂度。

刷新失败且已有旧快照时继续显示旧快照，并明确呈现「刷新失败，正在显示上次结果」与重试入口；写操作仍必须在原有写入 seam 重新验证目标并 fail closed。首次读取失败且没有旧快照时显示库级失败态，不伪装为空库。单个声音包的 manifest 或内容损坏只生成该包的 broken 事实，不让整个声音包库刷新失败；只有无法枚举声音包根等库级错误才进入 `failed(previous:error)`。
