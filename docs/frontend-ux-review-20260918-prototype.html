修复① 刷新失败提示（stale-while-refresh）

优先级 1

刷新失败但已有可用快照时，HEAD 对 .refreshFailed 渲染 EmptyView()，用户无从得知所看到的结果已过期。提案遵循 ADR 0002 的 stale-while-refresh 契约：事件区照常展示上次结果并保持可交互，在其上方增加一条轻量提示行（真红图标 + text-2 文案）与重试入口。切换下方场景对比两个面板的行为。

依据与口径

  • 现状澄清：面板没有常驻刷新入口——原有「重试」按钮只在 .loadFailed（加载失败、无可用快照）时出现；刷新本身在面板每次打开时自动触发。提案复用 panelRetry 文案与 retrySoundPackLibraryRefresh 动作，在 .refreshFailed（有旧快照）时提供重试；.refreshing 不显示常驻指示。
  • HEAD 缺口：PanelView.swift:678 —— case .ready, .refreshing, .refreshFailed: EmptyView()，三态合一，刷新失败无从呈现。
  • 契约来源：ADR 0002 stale-while-refresh —— 有陈旧快照时必须给出「刷新失败，正在显示上次结果」+ 重试。
  • 形态口径：复用共享 FailureRow（真红只做图标、文案 text-2），镜像管理窗已有的 .refreshFailed(reason:) 呈现（SoundPacksWindowAccessibility.swift:390）。
  • 非阻塞：提示行不替换事件区，事件行静音/试听保持可用。

修复② surfaceSoundIssue 恢复即解除（fail-closed 但可恢复）

优先级 2

写入失败后，surfaceSoundIssue 单一呈现失败行并禁用该来源的静音/试听（fail-closed，保留）。但 HEAD 只在写成功、重置覆盖或切换来源时清除它（PanelConfigController.swift:328 / 431 / 612 / 655）；底层自行恢复后重载配置（reloadConfigReadModel，:668）不会解除——控件持续禁用且没有任何解释。提案：重载时发现条件已恢复即同步清除。点击下方按钮看两个面板的差别。

  • 写允许门：PanelView.swift:595 configWritesAllowed: panelModel.surfaceSoundIssue == nil —— 清除后控件自动恢复，无需改视图层。
  • 单一呈现：PanelView.swift:769-771 失败行走 FailureRow，置 nil 即整体移除。

修复③ 错误文案：双语 + 可行动 + 按需恢复入口

优先级 3
